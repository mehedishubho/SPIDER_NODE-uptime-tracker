## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis lock state → write authority | Lock ownership gates who may write a transition; Redis is hardened but Postgres guards remain the authority |
| check outcome → Postgres transition writes | Outcome data (status, errorClass) crosses into authoritative rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-13 | Tampering | double-application of transitions on duplicate delivery | critical | mitigate | Conditional UPDATE (status guard) + partial unique ONGOING index + evidence-first ordering; duplicate-delivery test is the proof (DAT-01/04) |
| T-04-14 | Tampering | lock released/stealed by non-owner enabling concurrent writers | high | mitigate | Owner-token Lua compare-and-delete + TTL + abort-on-loss re-check before commit (WRK-04) |
| T-04-15 | Tampering | corrupted counters from concurrent Tier 1 + Tier 2 writers | high | mitigate | Additive UPDATE expressions + write_guards (04-05) + never-write-status rule on Tier 2; D-37 dry-run audits drift |
| T-04-16 | Information Disclosure | transition payloads in logs | low | mitigate | pino bindings carry ids/timings only; outbox payload fields limited to rendering needs (no user PII beyond what Telegram templates already carry) |
</threat_model>
