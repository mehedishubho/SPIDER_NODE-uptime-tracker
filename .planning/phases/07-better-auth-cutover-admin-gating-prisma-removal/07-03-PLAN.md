This plan carries 24 files (18 modified + 6 deleted; Task 2 alone touches 12) against an estimate of 0.90 of the context budget with uncalibrated confidence. The breach is accepted deliberately rather than split; splitting the ten-route sweep into its own plan was considered and REJECTED because:

1. **The sweep is atomic by design.** All ten routes import `authOptions` from `@/lib/auth` [VERIFIED: src/app/api/monitors/route.ts:1, src/app/api/feedback/route.ts:3]. Splitting the sweep off would force the rewritten auth.ts to keep exporting a legacy `authOptions` across a plan boundary — the legacy engine still serving ten routes' sessions between plans — which is precisely the dual-source state this plan's assumption_delta_decision, D-20 (no dual-source code), and D-29 (installed-but-serving-nothing) forbid. The split route trades context headroom for an invariant violation.
2. **Task 2's diff density is bounded and mechanical.** Per route the change is two import lines plus the guard call-site swap to `getAuthSession()` with null-check/401 semantics and ownership scoping preserved verbatim (one to three call sites per route — monitors/[id] three, monitors/route.ts two). No design decisions are made on those files; the only novel logic in Task 2 is the feedback admin gate and its D-16 audit line.
3. **The safety net is layered and already planned.** Task 2 is gated by typecheck (`authOptions` ceases to exist), the rg region gate (no `getServerSession|authOptions` under src/app/api or src/proxy.ts), and the Phase-6 contract suites (tests/api/monitors.handler.test.ts, tests/api/monitors-id.handler.test.ts) that pin the swapped guards' behavior.
4. **Context concentration sits in Task 1, not the sweep.** The parity-config/hook/behavioral work is the dense novel content; it is protected by executing Task 1 first with its own integration-suite verify before the mechanical sweep begins.

Executor guidance: work Task 2 strictly route-by-route (feedback first — it carries the only new logic), running the Phase-6 contract suites after each batch, so any regression surfaces within a two-file diff.
</scope_note>
