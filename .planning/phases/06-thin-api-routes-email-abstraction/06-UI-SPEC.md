# Phase 6 — UI Design Contract

**Zero-visual-change posture:** No new components, pages, tokens, or layout changes. Existing Phase 2 theme tokens, Sonner toaster, and button markup are inherited unchanged. The visual redesign is Phase 8 (UI-01..UI-05) — nothing here may pre-empt it.

| Element | Copy |
|---------|------|

| Checking state label | `Checking…` — swapped into the button's `title`/`aria-label` while checking (icon-only form preserved; no visible text added) |
| Empty state heading | N/A — no new empty states; dashboard empty state untouched |
| Empty state body | N/A |

## Interaction Contract — Check-Now Flow (the phase's one UI surface)

Implements D-01..D-06. Component: `src/components/Dashboard/Dashboard.tsx` (`handleCheckMonitor` + manual-check button, current lines ~184-205, ~603-618).

| State | Trigger | Visual | Behavior |
|-------|---------|--------|----------|
| Idle (active monitor) | default | RefreshIcon static, button enabled | POST `/api/monitors/[id]/check` on click |
| Checking | POST in flight OR poll window open | Button disabled, `animate-spin text-primary` (existing classes), label `Checking…` | Poll every 2s via the existing monitor read; completion = `lastChecked > queuedAt` |
| Result | poll detects completion | — (toast only) | Result toast (UP success / DOWN error) per copy table; button re-enables |
| Give-up | 30s deadline passes | button re-enables | Quiet-handoff info toast; polling stops; NO error state; NO auto re-enqueue |
| Rate-limited | 429 + `Retry-After` | button re-enables immediately | Friendly 429 toast with seconds from header; no auto retry |
| Inactive monitor | `!monitor.isActive` | disabled (existing condition, preserved) | No change to current behavior |
| Service unavailable | 503 from enqueue | — | Error toast from server copy; button re-enables |

**Poll contract (D-01/D-02):** poll the existing monitor list read (`fetchMonitors`) every 2s, give up after 30s; completion is `lastChecked` advancing past the enqueue timestamp. Zero new endpoints; the client never reads BullMQ job state.

**Timer discipline:** the 2s poll loop must stop on completion, give-up, or unmount (clear pending timeout in cleanup). Full AbortController-on-fetch hardening is Phase 8 UI-04 — out of scope here, but the loop may never outlive the component.

**Button markup rule:** the manual-check button keeps its current classes and icon-only form; the ONLY permitted markup deltas are the state label swap (`Checking…`) and the poll-driven behavior. Any other visual change belongs to Phase 8.
