# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase posture:** this is a backend-modernization phase with a MINIMAL UI surface. Per 07-CONTEXT.md D-33, all auth pages (login/register/forgot/reset/verify/verify-sent) keep their **exact current pixels** — only the auth client plumbing swaps (NextAuth → Better Auth `authClient`). The **only** new user-visible element this phase builds is the persistent, non-dismissible notice strip on `/login` (D-02, AUTH-06). Bull Board (D-18/D-19) is off-the-shelf operator console UI on the worker's :9090 — explicitly OUT of custom design scope. **No new design tokens, no `globals.css` edits, no new packages** (the Phase-2 byte-identity and zero-hex gates stay green).

## New Component Contract: Login Notice Strip

The phase's single build target. Source of truth: 07-CONTEXT.md D-02, D-03, D-05, D-06.

| Property | Contract |
|----------|----------|
| Route | `/login` only (not register/forgot/reset/verify — D-02 names /login) |
| Rendering | **Server-side**: the page reads the env-dated window (`notice` start/end envs — exact env names are planner territory per D-05) and renders the strip only inside the window. **Zero client state, zero client persistence** — no localStorage, no dismissal, no cookie |
| Placement | First child of the centered `max-w-md` column on the login page, full column width, `mb-4` (16px) above the existing brand header. In-column placement (not a viewport-wide banner) avoids colliding with the auth layout's absolute ThemeToggle (top-6 right-6) and guarantees visibility without scrolling at any viewport (`source: default (no user input available)` — D-02 says "persistent strip on /login" without placement detail) |
| Visibility | Non-dismissible; no close affordance; present on every /login render during the window (mid-session 401 redirects land here and see it — D-03) |
| Anatomy | `flex` row: `InformationCircleIcon` (w-4 h-4, muted) + text; `items-start` so wrapped lines align to the text edge, `gap-2` (8px); padding `py-4 px-4`; `rounded-xl`; tokens per the Color table |
| Text behavior | 14px/400/1.5; **wraps, never truncates** — copy must survive multi-line without clipping or ellipsis |
| Accessibility | `role="status"` so screen readers announce it; visible text carries the meaning (icon is decorative, `aria-hidden`) |
| Cleanup | Strip component + env reader + env entries are deleted with the deletion release (D-05 extends the D-41 remnant gate to the envs and any script) |
| Copy | Exactly the Copywriting Contract row above |

## Off-the-Shelf Surface: Bull Board (framing only)

Bull Board (OBS-04/SEC-04, D-18/D-19) is **exempt from this entire contract** — it is the library's own console, mounted on the worker's existing :9090 HTTP server under `/admin/queues`, gated IP-allowlist-first then Better-Auth-admin-session. The contract for it is deliberately three prohibitions and one note:

1. **No custom theme work** — do not restyle, re-brand, token-map, or wrap Bull Board's default UI; it is an operator tool, not a product surface.
2. **No BullMQ/web-bundle coupling** — it lives in the worker process; the web app stays a pure Postgres reader (D-18) and gains zero UI code from it.
3. **No mutation removal** — retry/remove/drain stay enabled (D-19); every hit already logs the D-16 structured audit line (backend concern, no UI element).
4. Framing note: the runbook documents the URL (`:9090/admin/queues`) and the two gates; no in-app link is built (no admin UI pages exist — D-14/D-15).

## Reuse Contract: Swapped Pages (D-33)

For login/register/forgot/reset/verify/verify-sent the visual contract is **identity, not specification**:

- Every class, spacing value, icon, label, and toast string stays byte-identical; only `signIn`/provider calls swap to the Better Auth client (`authClient`).
- Loading states keep their current form: inline spinner + "Signing In..." label and disabled buttons (no skeletons introduced).
- Error surfacing keeps its current form: sonner toasts with the pinned parity strings (no inline field errors introduced).
- The verify/reset pages' existing expired/invalid-token error states are the D-20 dead-link destination — unchanged.
- Diff expectation for these files: import lines and handler bodies only. A className diff on these files is a D-33 violation.
