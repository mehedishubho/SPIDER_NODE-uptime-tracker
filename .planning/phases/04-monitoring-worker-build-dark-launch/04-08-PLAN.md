    Create the seven case files, each seeding unique-suffixed monitors via raw SQL and asserting against both Postgres and the worker's /metrics.json or queue APIs. (1) duplicate-delivery: enqueue the same check jobId twice (or process the same job twice), assert exactly ONE ping row exists for that epoch and counters moved once. (2) kill-mid-job: add a test-only checkpoint hook in the check processor (env-gated, e.g. WORKER_TEST_CRASH_AFTER=tier1_commit making the process hard-exit via process.kill(process.pid, SIGKILL) equivalent immediately after the Tier 1 COMMIT and before the job ack) — spawn the real bundle on a DOWN-bound monitor, wait for the checkpoint marker, verify the process is dead, restart the worker, let the stalled job/redelivery settle, then assert: counter deltas exactly one transition's worth, exactly one ONGOING incident, no duplicate outbox row (D-29). The hook must be env-gated and documented as test-only. (3) postgres-down: stop the Postgres container (docker compose stop), enqueue checks + drive the breaker, assert jobs sit retryable (attempts > 0, not lost), breaker reaches OPEN with enqueue paused (canEnqueue false via behavior: enqueue helper refuses), restart the container, assert recovery to CLOSED and jobs complete. (4) redis-down: stop the Redis container, assert the worker does not fall back to any local scheduling (no new pings appear for due monitors — monitoring pauses by design), Postgres rows remain intact (checksum a table snapshot before/after), restart Redis and confirm recovery. (5) lock-loss: start a check, externally DELETE the lock key mid-job (via the admin Redis client at the injectable checkpoint), assert the Tier 1 write is aborted — no incident, no counter move, abort logged. (6) redis-restart: with the scheduler enabled on seeded due monitors, restart the Redis container (AOF persistence from the hardened image config or the test image default — document whichever), assert schedulers re-upsert at the worker's next boot (re-spawn the worker), stale lock keys expire via TTL, and the next tick re-claims via next_check_at (monitors due again produce pings) (RES-05). (7) backlog-flood: enqueue a burst of routine checks exceeding ~2x the seeded active-monitor count, assert routine enqueues are dropped with the BACKLOG_DROP marker logged and the drop counter incremented in metrics, while an enqueued non-UP/transition job in the same window still processes (RES-02). Every case restores containers/keys in finally blocks (fail-loud teardown per the rehearse script conventions).
