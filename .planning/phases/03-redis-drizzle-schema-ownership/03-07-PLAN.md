<objective>
Wire schema-drift protection into the single local gate chain: an empty-diff gate (apply migrations → introspect with drizzle-kit pull → diff against the committed schema) and a repo-wide absence scan for the retired destructive push command — then mutation-prove both gates actually fail when they should, and keep the chain inside the five-minute budget.

Purpose: DRZ-03 (the empty-diff gate preventing silent drift — criterion 2's "blocks silent drift") and DRZ-02's completion ("no longer exists anywhere"). Output: drizzle.gate.config.ts, scripts/schema-gate.mjs, extended pnpm verify, and recorded mutation-proof + timing evidence.

## Phase Goal (user story)

**As a** SpiderNode user, **I want** the platform beneath my uptime monitors modernized — rate limiting that survives restarts and a schema owned by rehearsed, versioned migrations — **so that** my checks, alerts, and history keep flowing through every deploy without data loss or lockouts.

This plan builds the guardrail: after it, any future schema change that bypasses the versioned-migration path — or any resurrection of the destructive push habit — fails the operator's single gate command before it can ship.
</objective>
