<objective>
Take ownership of the schema's PROVENANCE: restore a fresh anonymizable production snapshot into a throwaway local container, generate src/db/schema.ts from the live DDL via drizzle-kit pull, hand-finish it against audit §11, and commit the full-DDL baseline migration plus the deterministic journal-stamp script that makes existing databases (rehearsal snapshot, production) skip the baseline forever.

Purpose: DRZ-01 — the schema is authored from live production DDL, never from schema.prisma; the baseline + stamp pair is the load-bearing mechanism (research Pattern 4) that 03-04's worker-prereqs migration, 03-05's rehearsal, and the first production deploy all stand on.

Output: drizzle.config.ts, src/db/schema.ts, drizzle/0000_baseline.sql + meta journal, scripts/stamp-baseline.mjs, .snapshots/ gitignored.

## Phase Goal (user story)

**As a** SpiderNode user, **I want** the platform beneath my uptime monitors modernized — rate limiting that survives restarts and a schema owned by rehearsed, versioned migrations — **so that** my checks, alerts, and history keep flowing through every deploy without data loss or lockouts.

This plan builds schema ownership's foundation: after it, the repo holds a Drizzle schema proven against real production DDL and a baseline+stamp mechanism that lets every environment — fresh test container, rehearsal snapshot, production itself — converge on one migration history without ever re-running existing DDL.
</objective>
