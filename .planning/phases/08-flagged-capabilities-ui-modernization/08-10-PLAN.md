## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/ai/* | untrusted prompt/evidence input crosses here (session-guarded, capped, rate-limited) |
| lib/ai -> external provider | AI_API_KEY crosses to a third-party API over HTTPS; streaming responses cross back |
| DB evidence -> LLM prompt | monitor names/URLs/incident text are untrusted-ish data injected into prompts |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-15 | Tampering | prompt injection via monitor names/URLs into post-mortem prompt | high | mitigate | evidence sections delimited as data in instructions; output is copy-only markdown rendered via a safe renderer (no raw HTML injection); nothing executes from output (D-13 no-write) |
| T-08-16 | DoS | cost abuse / provider spend | high | mitigate | per-user Redis buckets 10/h (D-08), input caps both-sides tested, maxRetries 0 (no silent retry spend), timeout bounds, D-10 per-request token line for anomaly visibility |
| T-08-17 | Spoofing | unauthenticated streaming access | high | mitigate | session guard runs before limiter/provider; flag-off = 404 before body read (no surface to probe, D-21) |
| T-08-19 | Elevation | IDOR on incident/monitor evidence | high | mitigate | ownership proven (monitor.userId === session.user.id) before any evidence query; handler test pins the foreign-monitor 404 with zero evidence reads |
| T-08-20 | Spoofing | rate-limit bypass via key spoofing | medium | mitigate | per-USER keys post-authentication (Pitfall 8) — IP headers never enter AI bucket keys |
| T-08-21 | Tampering | SSRF via assistant-generated URLs | high | mitigate | (assistant route lands in 08-07) post-mortem route takes no URLs as instructions; the create route re-runs assertUrlAllowed on submit — AI-04's same-schema gate includes the SSRF admission |
