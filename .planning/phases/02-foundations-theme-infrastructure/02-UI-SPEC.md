# Phase 2 — UI Design Contract

> Visual and interaction contract for the theme-infrastructure work (THM-01/02/03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a zero-visual-change phase. The contract's job is threefold: (1) freeze today's dark palette **byte-identically** under `.dark`, (2) define the first-pass light palette (zinc mirror, D-22) and the two curated status tokens (D-25), and (3) specify the only two new UI elements — the `ThemeToggle` and the `ThemedToaster` wrapper. Every existing screen, layout, spacing value, and copy string is **frozen**. Visual redesign is Phase 8 (UI-01..05) — out of scope here.

## Color

### Mode architecture (THM-01)

- `next-themes` with `attribute="class"`, `defaultTheme="dark"` (D-24), `enableSystem`, `disableTransitionOnChange`.
- `suppressHydrationWarning` on `<html>`; delete the hardcoded `className="dark"` from `src/app/layout.tsx` (the pre-paint script sets it before first paint — dark users see today's app pixel-for-pixel).

- `:root` becomes the **light** palette (below); `.dark` holds **today's values byte-identically** (source: current `:root` in `src/app/globals.css`, read 2026-09-10).

### Hex → token migration rules (THM-03, mechanical, ~254 occurrences)

Rule: **every raw hex in `src/` migrates to a token/utility with the SAME computed value in dark.** Only the curated set above (`:root` palette, status tokens, gradient start, destructive) gets different light values. Two exclusions:

1. `src/lib/mail.ts` (15 hexes) — email HTML cannot use CSS vars (RESEARCH-verified exclusion).
2. Google "G" brand-mark hexes in `LoginForm.tsx`/`RegisterForm.tsx` (`#4285F4` `#34A853` `#FBBC05` `#EA4335`) — brand marks keep identical values in both modes.

Recurring mappings:

| Hex (today) | Maps to |
|-------------|---------|
| `#EF4444`/`#ef4444` as button/bg/accent | `bg-primary` / `text-primary` (or `--destructive` where semantic is destructive) |
| `#EF4444` where semantic is DOWN state | `--status-down` |
| `#121212` as background | `bg-background` |
| `#121212` as text-on-red (buttons) | `text-primary-foreground` |
| `#0F172A`/`#0f172a` (slate-900 text on light/brand surfaces) | same-value token both modes (e.g. `--foreground-invert: #0f172a`) — already light-correct |
| `#A141FE` (Pagination active, DeleteModal) | same-value token both modes this phase (e.g. `--highlight-purple`) — Phase 8 reviews |
| `text-slate-100` (body) | `text-foreground` |
| emerald/red Tailwind classes carrying **UP/DOWN status semantics** (e.g. `text-emerald-400` status text, `bg-emerald-500/10` status chips) | `--status-up` / `--status-down` (dark value identical: `#34d399` = emerald-400, `#ef4444` = red-500) |

Left as-is this phase (Tailwind palette classes, not hexes — D-25 limits curation to UP/DOWN): `amber-*` paused/PENDING colors, `rose-*` degradation text, `slate-*` header chrome. Phase 8 UI-03 does the full per-hex/per-class review.

## Interaction Contract — the only new component

### ThemeToggle (`src/components/theme/ThemeToggle.tsx`)

| Aspect | Contract |
|--------|----------|
| Behavior | Single button cycling **Light → Dark → System → Light** (D-23); persists via next-themes localStorage key `theme` |
| Icons (hugeicons-react, repo `*Icon` convention) | `SunLightIcon` (light) · `Moon02Icon` (dark) · `Monitor01Icon` (system) |
| Tooltip | Existing shadcn `Tooltip` primitive (`src/components/ui/tooltip.tsx`) — no new deps; text shows current state (copy below) |
| Accessible name | `aria-label` on the button (tooltips are not accessible names) |
| Target size | 36×36px (`size-9`), matching the adjacent `NavUser` trigger; 18px icon; **documented sub-44px exception** — desktop-first dashboard, mouse-primary, consistent with neighboring header controls |
| Styling | `text-muted-foreground hover:text-foreground transition-colors`; `focus-visible` ring from `var(--ring)`; transparent background, no border |
| Hydration safety | `mounted` guard — render `<span className="size-9" aria-hidden="true" />` placeholder pre-mount (layout-stable, no mismatch); icon reflects **selected** theme, not resolved |
| Placement (2 surfaces) | (1) `AppHeader.tsx` right cluster, left of `NavUser`, `gap-3`; (2) `(authLayout)/layout.tsx` top-right, 24px inset — auth pages are pre-login, theme must be settable there too |
| Element | Native `<button type="button">` — Enter/Space keyboard support for free |

### ThemedToaster (`src/components/theme/ThemedToaster.tsx`)

- Client wrapper replacing the current server-rendered `<Toaster richColors position="top-right" theme="dark" />` in `src/app/layout.tsx`.
- Reads `useTheme().resolvedTheme`; renders `<Toaster richColors position="top-right" theme={resolvedTheme === "light" ? "light" : "dark"} />`.
- Props other than `theme` are frozen exactly as today (`richColors`, `position="top-right"`). No new toast content this phase.

## Behavior-Compatibility Invariants (verification hooks)

These are the UI gate for "dark visually identical to today" (ROADMAP success criterion 3):

1. **Dark byte-identity:** with `defaultTheme="dark"`, computed styles of representative surfaces (body bg, card bg, border, status text, buttons) are identical pre/post migration — verified by computed-style spot checks and e2e assertions on `documentElement.classList` containing `dark`.
2. **No FOUC:** next-themes pre-paint script sets the class before first paint; no white flash on load in either mode.
3. **No hydration mismatch:** zero React hydration warnings with the toggle and ThemedToaster mounted.
4. **Toasts follow resolved theme:** after toggling, toasts render in the active palette.
5. **Hex gate:** `rg "#[0-9a-fA-F]{3,8}" src/` outside the two exclusions (`mail.ts`, Google brand marks) → 0 after migration.
6. **Cycle order:** clicking from default state cycles Light → Dark → System → back; reload persists choice.
