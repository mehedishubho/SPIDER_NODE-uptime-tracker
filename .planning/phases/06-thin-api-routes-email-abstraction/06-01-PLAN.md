# Plan 06-01: Check-Now Enqueue Slice (202 + Poll)

## Phase Goal

**Roadmap goal (verbatim):** "The web app becomes a stateless producer — routes enqueue and never probe — and transactional email leaves the request path behind a provider interface."

**This plan's slice:** **As a** dashboard user, **I want to** click the re-check button and get an immediate response with the fresh result appearing within seconds, **so that** the web app stays responsive and no API route ever executes a check against a target itself (API-01, rules 4–6).

<objective>
Turn the manual-check path into the stateless-producer vertical slice: a bounded web-side BullMQ producer, the check-route rewrite to enqueue + 202 (API-01) with per-user rate limiting (SEC-05) and loud 503 degradation (API-02), plus the dashboard poll UX (D-01..D-06). RED tests first, then server, then client.

Purpose: This is the first half of the phase's headline behavior — the web process stops probing targets and becomes an enqueue-only producer.
Output: src/lib/queue-producer.ts, src/lib/api-error.ts, src/lib/check-now-poll.ts, rewritten check route, extended limiter, new test suites.
</objective>
