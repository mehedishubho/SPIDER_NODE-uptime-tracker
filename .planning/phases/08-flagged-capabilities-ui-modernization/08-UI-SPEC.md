## Typography

Refined scale (D-30) — scoped to the **redesign surfaces** (dashboard, monitor detail, dashboard-incidents, internal status, public status, AI surfaces). Auth + marketing keep their current sizes (palette/motion pass only, D-27). Exactly 4 sizes, exactly 2 weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label / meta | 12px (`text-xs`) | 400 | 1.5 |
| Heading | 18px (`text-lg`) | 600 | 1.2 |
| Display | 28px (`text-[28px]`) | 600 | 1.2 |

Rules:

- The scattered 10px/11px sizes (`text-[10px]`, `text-[11px]`) consolidate to the 12px Label role.
- Weights 500/700/800 retire across redesign surfaces — emphasis is 600 (metrics numbers drop `font-extrabold` for 600; this IS the type refinement of D-30).
- Fonts by role: body = Inter, Heading/Display = Space Grotesk, all data values (metrics, URLs, timestamps, status labels, uppercase micro-labels) = JetBrains Mono at the declared sizes. Uppercase micro-labels keep `tracking-wider`.
- No font wiring changes; no new families (D-30).

## Color

Both modes redesigned on the same token set; dark remains the default (D-31). Every color routes through the token system — the Phase-2 zero-hex gate stays in force.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` — #121212 dark (default) / #fafafa light | Page canvas, both modes |
| Secondary (30%) | `var(--card)` — #27272a dark / #ffffff light (with `--sidebar`, `--popover`, glass-panel tint) | Cards, sidebar, dashboard header strip, table shells, dialog surfaces |
| Accent (10%) | `var(--accent-cyan)` — #00E5FF dark; light gets a darkened text-safe variant set at the 11-token review (see Token Migration Rules) | Reserved list below — nothing else |
| Brand primary (CTA) | `var(--primary)` — #ef4444 both modes (`--ring` follows) | Primary CTAs (Add Monitor, Get Started), brand mark, focus rings — never status, never body text |
| Status up | `var(--status-up)` — #34d399 dark / #16a34a light | UP semantics only |
| Destructive / status down | `var(--destructive)` = `var(--status-down)` — #ef4444 dark / #dc2626 light | DOWN states + destructive actions only |

Accent (cyan) reserved for — explicit list:

1. Active sidebar navigation item (tint + text + border — today's `NavMain` active state, kept)
2. Uptime-percentage and latency value emphasis on dashboard + public status
3. Monitor-name link hover state
4. AI affordances: "Generate post-mortem" trigger accent, streaming caret + card border while streaming, assistant input focus accent
5. Skeleton shimmer tint (subtle)

Cyan is never used for: body text in dark mode over dark surfaces without the emphasis role, headings, CTA fills (brand primary owns those), status indication (status tokens own that), or large surface fills. Contrast rule: wherever cyan renders as text on a light background it uses the darkened light-mode variant at ≥ 4.5:1 (WCAG AA); #00E5FF remains valid for non-text accents (dots, borders, glows) in both modes.

## Token Migration Rules (UI-03 inputs — all mandatory)

1. **WR-02 surfaces (D-26):** Navbar/TeamSwitch `text-white` headings → `text-foreground`; AppHeader `bg-slate-950/80` → `bg-background/80` + `border-border`; marketing copy `text-slate-300/400` → `text-muted-foreground`.
2. **Mixed emerald/rose ternaries (02-08 carry-forward):** every status-colored `emerald-*`/`rose-*` utility (dashboard badges, incident icons, uptime values) migrates to `status-up`/`status-down` tokens.
3. **11 same-value tokens review (02-08):** the byte-identical `:root`/`.dark` set may now split per-mode where light legibility requires — primary candidates: `--accent-cyan`, `--muted-meta`, `--foreground-bright`, `--danger-strong`. `--dialog-*` retire with Swal's deletion (alert-dialog uses `--popover`/`--card`). Dark default values do not change (D-31: the freeze lifts for the redesign, not against dark).
4. **Slate hardcodes on redesign surfaces:** `text-slate-*`/`border-slate-800`/`bg-slate-900` → `muted-foreground`/`border`/`secondary` tokens; `text-white` → `text-foreground`.
5. **Light dashboard contrast + light toast aesthetics** (02-UAT Test-4 notes): light-mode card borders meet 3:1 against their surface; ThemedToaster keeps `richColors`/`top-right` and resolved-theme wiring.

## Interaction Contract — AI surfaces (AI-03 / AI-04 UX)

**Post-mortem card (monitor detail, per incident row):**

- Trigger: "Generate post-mortem" button on each incident row — visible only when `AI_ENABLED`; flag off = zero trace (D-21).
- Card renders inline under the incident (D-12) — never a modal hiding the evidence; mounts on the existing incident block structure (icon + title + description + started/resolved timestamps + ACTIVE/RESOLVED badge).
- Streams markdown live (AI SDK streaming hooks, D-07) with the four D-14 sections; controls per the copy table (Stop while streaming; Copy + Regenerate when complete).
- Copy-only: no save-to-incident affordance of any kind (D-13).
- Session read via the `useAuthSession` accessor (single-importer rule, 07 pattern); rate limits per D-08 buckets.

**Monitor-setup assistant (Add Monitor dialog, create only — D-17/D-18):**

- The "Describe it in plain words" input sits above the three existing fields (Monitor Name, Target URL, Check Interval 1/5/10/30/60); Edit keeps the plain form.
- Suggestion streams into the form fields; partial fill + inline hints per D-19; normal form submit is the confirmation and the schema stays the single gate (AI-04).

**Robustness rules (UI-04 — interaction level):**

- AbortController on every polling fetch — the 30s refresh fetches in Dashboard/MonitorDetails/PublicStatus gain the abort discipline the check-now poll already has (06-01 pattern).
- All interval timers clear on unmount (existing `clearInterval` discipline stays a verify gate).
- URL derivation is hydration-safe: build URLs from route params/after mount, never `window` during first render.
- Exactly one Toaster (root `ThemedToaster`).

## Motion & Micro-interactions (D-28 — motion v12 only)

- Staggered list entrances: today's CSS `animate-fade-in-up` + delay classes migrate to motion v12 variants; 50ms stagger per item, capped at 8 items (rest appear together).
- Status-change transitions: status dot/badge crossfades 200ms; numeric values keep the `transition-number` color/opacity fade.
- Skeleton loaders: `skeleton.tsx` pulse ~1.5s, subtle cyan shimmer tint allowed.
- No page-transition theatrics, no new Lottie (existing `Loading.tsx` / `PageNotFound.tsx` Lottie get light-safe asset treatment only, UI-03).
- Every motion above honors `prefers-reduced-motion` with a static fallback (motion v12 `useReducedMotion`).
